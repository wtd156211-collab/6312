# 插值方法与边界（从 0 实现）

起始环境只有本说明、`samples/**` 与 `.gitignore`：引擎、命令行入口和那页图都从 0 写，入口是
仓库根目录的 `interp.py`；交付物是引擎与它生成的 `interp.html`。Python 3.13 标准库，
不引第三方、不加构建、不联网，测试写在 unittest 里。

## 一、范围

做：读入「采样点 + 查询位置」→ 按场景选线性或自然三次样条 → 算每个查询位置上的取值 →
逐条核对 `samples/expected/**` → 生成单文件 `interp.html`（采样点、插值曲线、陡变处的放大窗口、
方法与最大越界量，数据内联、双击即开）。

不做：二维或网格插值、参数曲线、闭合曲线；拟合与回归（曲线必须穿过采样点）；平滑、滤波、去噪；
端点外推（范围外一律截断）；重复位置取值冲突时的合并或平均；数据库、网络、多进程多线程；
除 `var/` 与 `interp.html` 外不落盘，`samples/**` 只读。

## 二、口径与公式

### 2.1 采样点

位置 x 非降序；去掉重复后至少两个点，h_i = x_{i+1} − x_i > 0；间距均匀或不均匀都允许，
公式里一律用真实 h_i。同一位置的重复点：取值相同并成一个点，取值不同是输入错误。

### 2.2 线性

区间 [x_i, x_{i+1}] 上 S(x) = y_i + (x − x_i)·(y_{i+1} − y_i)/h_i；采样点处原样通过。

### 2.3 自然三次样条

端点二阶导为 0（M_0 = M_n = 0），内部节点满足

    h_{i−1}·M_{i−1} + 2(h_{i−1} + h_i)·M_i + h_i·M_{i+1}
        = 6·((y_{i+1} − y_i)/h_i − (y_i − y_{i−1})/h_{i−1})

这是三对角方程，自己写求解，间距不均匀时同样成立。区间上用 t = x − x_i、
b_i = (y_{i+1} − y_i)/h_i − h_i·(2M_i + M_{i+1})/6 求值：

    S(x) = y_i + b_i·t + (M_i/2)·t² + ((M_{i+1} − M_i)/(6·h_i))·t³

n = 2 时样条退化成直线，直接走线性。

### 2.4 场景与方法（写死，以文件头 `# scene` 为准）

| scene | 场景 | 方法 |
| --- | --- | --- |
| `smooth` | 平滑段，间距均匀或不均匀 | 自然三次样条 |
| `steep` | 陡变 | 线性 |
| `plateau` | 平坦段 | 线性 |
| `endpoint` | 极值落在端点 | 线性 |
| `two` | 只有两个采样点 | 线性 |

为什么这么分：样条光滑，但会在陡变两侧、平坦段边缘、端点附近冲出数据取值范围，造出数据里
没有的峰；这几类场景保形优先取线性，只有平滑段用样条。取舍写在这里，实现里不许再按数据猜。

### 2.5 边界与越界量

查询位置落在 [x_0, x_n] 内按上表求值；x < x_0 取 y_0，x > x_n 取 y_n（截断，不外推），
越界标记 low / high。越界量 = 结果折线（[x_0, x_n] 上 2001 个等距位置，含两端）超出
[min y, max y] 的最大值；线性组恒为 0。

## 三、数据结构与流程

一条序列 = 场景标签 + 去重后的采样点 + 查询位置表；引擎给出方法名、二阶导数组（走线性时为
空）、每个查询的取值与越界标记、越界量。

流程：解析 → 校验（非降序、同位置同取值、至少两点）→ 去重 → 按 scene 选方法 → 建样条 →
逐查询求值 → 与期望逐条核对 → 渲染 HTML。每个查询只有 in / low / high 三种终态。

## 四、输入输出与文件格式

文件都用 UTF-8 无 BOM、`\n` 换行、末行有换行。

### 4.1 序列文件 `samples/series/<名>.txt`

`#` 开头是头信息与注释，其中必须有一条 `# scene <标签>`（取值见 2.4）和一条
`# query <位置> [<位置> …]`（空格分隔，至少一个，允许范围外）；其余非空行是 `<x> <y>`，
十进制数，x 非降序。

### 4.2 期望文件 `samples/expected/<名>.txt`（与 `samples/series/<名>.txt` 同名）

首行是 `# series=<名> method=<linear|spline> tol=<绝对容差> overshoot=<越界量>`，其后每行
`<位置> <期望取值> <in|low|high>`。逐行核对：|引擎值 − 期望值| ≤ tol；low / high 还要与
端点采样值之差 ≤ 1e-9；overshoot 与引擎的越界量之差 ≤ tol。容差统一 1e-6，例如
`# series=03_steep method=linear tol=1e-6 overshoot=0.000000000`。

### 4.3 命令

```
python interp.py run    <序列文件>
python interp.py report [<样例根>=samples] [<输出>=interp.html]
```

`run` 每个查询一行：

```
x=<位置> y=<取值，9 位小数> method=<linear|spline> edge=<in|low|high>
```

`report` 按文件名字升序核对 `expected/*.txt`：全部一致时打印一行 `ok=<组数>` 并写 HTML；
有不符时每处一行 `mismatch=<序列> x=<位置>`，退出码 1、不写 HTML。退出码：0 成功；1 有不符；
2 用法或输入错误（stderr 一行 `error: …`）。

### 4.4 页面 `interp.html`

单文件、双击即开：没有外链（外链 css/js/图片一律不许），数据内联。每组一节，
标注组名、方法、采样点数、越界量与查询取值，画出采样点和结果折线，陡变组带一块放大窗口。
数字与折线坐标都来自引擎输出，页面只做坐标映射与绘制、不重算插值；引擎把每组的方法、
越界量与折线点以 JSON 内联在 `<script type="application/json" id="interp-data">` 里供核对。

## 五、性能与验收口径

测试环境：Python 3.13、单进程单线程；墙钟用 `time.perf_counter`（不含解释器启动），内存用
`tracemalloc` 扣基线。

1. 逐条核对：`report` 必须给出 `ok=8`，8 组共 79 行期望没有一处不符。
2. 规模：`08_scale` 是 1 000 000 个采样点（约 13.9 MB 文本），`run` 端到端 ≤ 20 s、峰值内存
   ≤ 512 MiB；其余七组每组 ≤ 1 s；`report` 全量 ≤ 30 s。
3. 保形：陡变、平坦段、端点极值、两点四组的越界量必须为 0；平滑四组与 expected 里的
   overshoot 相差 ≤ 1e-6（都不超过 1.7×10⁻⁵）。陡变组误用样条会得到 0.2765 的越界量，
   越界点附近的取值也对不上。
4. 平稳：平滑四组必须走样条；采样点处原样通过（差 ≤ 1e-9）。两种方法在查询点上的最大差为
   0.0263（01）、0.1557（02）、0.0155（07）、5.6×10⁻⁴（08），远大于容差，逐条核对即可分辨。
5. 确定性：同一输入连跑两遍，stdout 与 HTML 逐字节相同；换工作目录、换
   `PYTHONHASHSEED` 也一样；不写时间戳、随机数、绝对路径、进程号。只用标准库，除 `var/`
   与 `interp.html` 外不改动任何文件。

## 七、待补的文档

- 坏输入（位置下降、同位置不同取值）的期望输出还没有样例，口径见 2.1 与 4.3。
- 页面配色、版式与放大窗口的取法自定；查询取值表在页面上的排布未固化。
- 更大规模（千万级采样点、上千个查询）与多序列批处理的输入格式还没定。
